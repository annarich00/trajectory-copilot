# `examples/benchmark_case_b_boundary/` — TJC-1.9 boundary-case GMAT evidence

Committed GMAT evidence for the four-category rendezvous benchmark's
boundary case (`evaluations/benchmark/case_b_boundary_cw.json`): the same
circular-LEO quarter-period CW rendezvous geometry as
`examples/cw_gmat_vertical_slice.yaml`, but requested over a **half**
orbital period instead of a quarter. At that exact transfer time,
`src/cw.py::two_burn_targeting` reports `Phi_rv` as singular but reachable
(`status="singular-reachable"`), which is exactly the targeting-conditioning
signal `src/model_selector.py` uses to return a **qualified** CW decision
(`qualified=True`) rather than a clean pass or a rejection.

- `verification_result.json` — the full structured result from a real run
  against `GmatConsole-R2026a` (using a GMAT script generated by
  `src/gmat_verify.py::generate_gmat_script`, unmodified, called as a black
  box by `scripts/generate_benchmark_gmat_evidence.py`), reaching
  `"verified": true` (position error ~0.046 m, velocity error ~3.07e-5 m/s,
  both inside the 1 m / 0.001 m/s tolerances) despite the singular-reachable
  targeting conditioning. The generated `.script` file itself is not
  committed (regenerated by every run), matching
  `examples/cw_gmat_slice_example/`'s convention of committing only the
  result/screenshot.
- `trajectory.svg` — the deterministic SVG trajectory plot artifact.

Reproduce with:

```
.venv/bin/python scripts/generate_benchmark_gmat_evidence.py --gmat GmatConsole-R2026a
```

This directory does not modify `scripts/run_cw_gmat_slice.py` or
`src/gmat_verify.py`; it only calls their existing public functions for a
different fixed transfer time.

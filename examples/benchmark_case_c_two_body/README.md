# `examples/benchmark_case_c_two_body/` — TJC-1.9 CW-invalid/two-body GMAT evidence

Committed GMAT evidence for the four-category rendezvous benchmark's
CW-invalid/two-body case (`evaluations/benchmark/case_c_two_body.json`): a
declared point-mass coast state for a LEO chaser offset radially by
1,000 km from a 6,778 km reference radius (a ~14.8% separation ratio — not
local CW proximity motion). `src/model_selector.py` marks `locality` and
`other_physics` as `violated` and routes this to the bounded two-body
fallback (`src/twobody.py::propagate_cartesian_state`), not CW.

- `verification_result.json` — the full structured result from a real run
  against `GmatConsole-R2026a` (propagating the same initial inertial
  Cartesian state under GMAT's own zero-degree/order (point-mass) force
  model in the `EarthMJ2000Eq` frame, the same frame/state convention
  `src/twobody.py` declares, `reference/SOURCE.md` Sec A.2, via a script
  generated by `scripts/generate_benchmark_gmat_evidence.py`, which calls
  `src/gmat_verify.py::check_gmat_available`/`run_gmat_script` as a black
  box and does not modify that module):
  `src/twobody.py::propagate_cartesian_state`'s analytical-RK4 final state
  compared to GMAT's independently propagated final state, reaching
  `"verified": true` (position error ~0.0022 m, velocity error ~5.25e-6
  m/s, both well inside the 1 m / 0.001 m/s tolerances). The generated
  `.script` file itself is not committed (regenerated by every run),
  matching `examples/cw_gmat_slice_example/`'s convention of committing
  only the result/screenshot.
- `trajectory.svg` — the deterministic SVG trajectory plot artifact (the
  coast displacement in the orbital plane over the 900 s duration).

Reproduce with:

```
.venv/bin/python scripts/generate_benchmark_gmat_evidence.py --gmat GmatConsole-R2026a
```

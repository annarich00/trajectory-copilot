## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The operator pasted a persistent 'GMAT GUI Script Generation Standard' describing what a well-designed GMAT GUI script should contain: organized/commented sections, a multi-view OpenFrames layout (Earth-centered global view plus a Chief-centered close-up rendezvous view), visible spacecraft differentiation, mandatory maneuver visualization (burn-location markers, delta-v direction vectors, delta-v magnitude labels, pre/transfer/post orbit segment distinction, maneuver timing), scale/visibility tuning, and a documented set of final deliverables. An evaluating subagent compared this document against TJC-10 through TJC-15 and found it does not fit any of them: TJC-10/TJC-11 are about researching and structuring an external open-source GMAT script corpus; TJC-12/TJC-15 are about tool-call plumbing and sequencing; TJC-14 is explicitly and narrowly scoped to citing that external corpus when reviewing formatting/convention, never to generation/design. The TJC-16 family is also a mismatch: it covers matplotlib/plotly Python plots from numeric state histories, a different artifact medium than GMAT's own .script/OrbitView/OpenFrames GUI configuration.

Confirmed generator-function relationships (read directly from src/gmat_verify.py and its callers before scoping this task further): there are exactly four script-generation functions, split into two functionally distinct pairs, not four interchangeable variants.

- generate_gmat_script (CW case) and generate_two_body_coast_script (two-body case) are both console-mode, ReportFile-only numeric verification scripts with ZERO OrbitView/visualization content. They are called from scripts/run_cw_gmat_slice.py, scripts/generate_benchmark_gmat_evidence.py, and src/workflow.py::_run_two_body_path respectively, and are explicitly OUT OF SCOPE for this task -- they have no visualization surface to upgrade and must not be touched.
- generate_gmat_gui_preview_script (CW case) and generate_two_body_gui_preview_script (two-body case) are the only two functions with a real OrbitView/ShowPlot=true resource. generate_gmat_gui_preview_script is called from scripts/run_cw_gmat_slice.py (itself invoked by src/workflow.py::_run_cw_path indirectly) and tests/test_cw_gmat_slice.py; generate_two_body_gui_preview_script is called directly from src/workflow.py::_run_two_body_path. These two functions, and only these two, are this task's target: the shared visualization helpers this task introduces belong between this GUI-generator pair, not spread across all four functions.

Preserve both GUI generators' existing public call signatures (keyword-only radius_m/deputy_state0_si/dv0_mps/dv1_mps/transfer_s for the CW one; state0_si/mu_m3_s2/duration_s for the two-body one) unless a change is justified and documented -- existing callers (scripts/run_cw_gmat_slice.py, src/workflow.py, tests/test_cw_gmat_slice.py) must keep working. Do not create a third, independent script-generation path; extend these two functions (and factor out genuinely shared helper logic between them) rather than duplicating visualization logic.

This task upgrades the GMAT GUI script generators themselves for a comprehensible, single-script, multi-view maneuver visualization -- it does not add a corpus-comparison review capability (that remains TJC-14's separate, narrower scope) and does not add new matplotlib/plotly demo plots (that remains the TJC-16 family's separate scope).
